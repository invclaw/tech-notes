> [!FOCUS] 两条硬核原则
> 1. **扩展优先于内置**：与其把 Plan Mode、Sub-agents 写死成官方唯一解法，不如把扩展接口做得足够强，让社区用 TypeScript 模块自己长出任何工作流；
> 2. **安全边界交给真正的隔离层，而不是脆弱的内置弹窗**：Pi 刻意不内置文件系统/网络权限拦截器，而是提供清晰的**外置容器与微虚机隔离模式**，并在 npm 依赖供应链上做了教科书级加固。

---

## 1. 全权 TypeScript Extensions 与资源包体系

在 Pi 中，**Extensions** 是直接加载到 Pi 进程内的 TypeScript 模块，拥有极高的定制自由度：
- 可注册自定义工具、斜杠命令、快捷键、自定义模型 Provider、事件监听（如介入 `session_before_compact` 改写压缩策略）、自定义终端渲染器与交互 UI；
- 配合 **Skills（按需加载的领域指令与附带脚本）**、**Prompt Templates（输入展开模板）** 与 **Themes**，可以整体打包为 **Pi Packages** 通过 npm 或 Git 分发；
- 加载项目级配置与扩展前，Pi 会先完成 **Project Trust（项目信任判定）**，防止打开陌生仓库时自动执行不受信任的项目脚本。

---

## 2. 外置隔离：为什么不内置沙箱，以及 4 种官方隔离模式？

Pi 在文档中非常坦诚：**内置权限弹窗既拖慢开发节奏，又很难做成真正的安全边界**。默认情况下 Pi 以启动它的 OS 用户权限运行；一旦需要强隔离，官方推荐根据场景选择 **4 种外置隔离方案**（与 [AI Agent 沙箱技术全景](#/agent-sandbox/overview) 的 L3/L5 层级直接对应）：

| 隔离模式 | Pi 进程跑在哪 | 隔离范围 | 凭据（API Key）放哪 | 核心取舍 |
|---|---|---|---|---|
| **1. Plain Docker** | 容器内 | Pi + 内置工具 + `!` 命令 + 扩展全进容器 | 需传入容器环境变量 | 最简单直白，但容器内恶意代码能读到传入的 Key |
| **2. Docker Sandboxes** | 托管沙箱内 | 整进程与扩展全隔离 | **真实 Key 留在宿主机代理**，容器内只放占位符，出站时由代理动态替换 | **强烈推荐的凭据保护模式**：沙箱被攻破也偷不到真实 API Key |
| **3. NVIDIA OpenShell** | 本地/远端托管沙箱 | 整进程 + 策略级文件系统/网络/凭据隔离 | 由 OpenShell 网关统一策略管控 | 适合需要精细企业级出网与推理路由策略的场景 |
| **4. Gondolin 扩展** | **宿主机** | 仅内置工具与 `!` 命令进**本地 Linux MicroVM** | Pi 与存储凭据留在宿主机 | 保留宿主机原汁原味的终端/配置体验，同时把命令执行关进独立内核 MicroVM（注意：未接入 Gondolin 的其他扩展工具仍在宿主机跑） |

## 3. 值得借鉴的 npm 供应链防投毒实践

作为需要高权限运行在开发者本机的 CLI，Pi 对自身依赖供应链的防御非常严苛：
- **精确锁定 + 冷静期**：直接依赖全部精确锁版本，且设置 **`min-release-age=2`**——拒绝安装发布不满 2 天的最新 npm 包，避开“刚投毒上架就被秒装”的零日供应链攻击；
- **默认禁用安装脚本**：本地安装、官方安装器与 CI 全程强制 `--ignore-scripts`，并对允许执行生命周期脚本的依赖维护显式白名单，新增即触发 CI 拦截人工审查；
- **离线确定性打包**：通过锁定的模型目录快照支持完全离线构建与 Nix 源码复现。
