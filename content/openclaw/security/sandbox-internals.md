## 1. 本地容器的四重底层加固原理（Docker / Podman）

默认本地沙箱并不是裸跑一个普通容器，而是叠加了四层最小权限约束：

1. **默认彻底断网（Network Namespace 隔离）**：
   - 默认以无网络模式（`network: none`）启动，容器内没有任何外网或宿主机局域网出口，直接切断反弹 Shell、凭据外传和内网横向探测。
2. **只读根文件系统 + 限容内存盘（Read-only Root + Capped tmpfs）**：
   - 容器根文件系统默认设为只读，防止恶意脚本篡改系统二进制或留下持久化后门；
   - 只有 `/tmp`（上限 1 GiB）、托管依赖缓存（上限 4 GiB）及 `/var/tmp`、`/run`（上限 256 MiB）挂载为可写内存盘 `tmpfs`——容量封顶防止进程恶意写满宿主机内存，且容器停止即清空。
3. **剥离全部内核能力 + 禁止提权**：
   - 启动时丢弃全部 Linux Capabilities（`capDrop: ALL`）、开启 `no-new-privileges` 标志（阻断 setuid/setgid 提权），并注入内置 `init` 进程回收孤儿/僵尸进程；
   - 容器用户默认自动对齐挂载工作区在宿主机上的 `uid:gid`，避免容器写出的文件在宿主机上变成 root 归属导致权限混乱。
4. **宿主机凭据默认隔离**：
   - 宿主机的环境变量、用户家目录与托管 GitHub 凭据默认都不传入容器；沙箱内命令的 `HOME` 默认重定向到沙箱工作区根目录。只有管理员显式开启高风险选项时，才以只读方式挂载特定凭据（且在全局共享容器中直接禁止注入凭据）。

## 2. 工作区可见性与文件桥接原理

### 2.1 工作区三级可见性
沙箱能看到宿主机工作区的多少内容，由三级模式精确控制：
- **`none`（默认最严）**：完全不挂载 Agent 宿主机工作区，只给一个私有的隔离沙箱目录；
- **`ro`（只读）**：将宿主机工作区以只读方式挂到 `/agent`，所有写/改/补丁操作一律被拒绝；
- **`rw`（读写）**：将宿主机工作区以读写方式挂到 `/workspace`。
- **访客强制封顶**：当会话创建者的角色要求“强制沙盒”时，即使全局配了 `rw`，系统也会**硬性封顶为 `ro`**，防止访客改写共享 Agent 工作区。

### 2.2 文件工具不走“宿主机直读”，而是走 SandboxFsBridge
- 在沙箱开启时，`ls` / `read` / `write` / `edit` 等文件工具**绝不回退直接读取宿主机文件系统**，而是通过统一的**沙箱文件系统桥接层**：
  - 本地容器会核对容器挂载表，只放行真正有宿主机绑定映射的路径；如果某个路径被容器内 `tmpfs` 或镜像卷遮挡，文件工具会直接拒读底层被遮挡的宿主机文件，防信息泄漏；
  - 远端后端（SSH / OpenShell / Crabbox）通过对应远程通道读写；
  - 同一物理文件的并发操作在 Gateway 内严格串行化，防止多工具并发写坏文件。
- **额外挂卷防符号链接逃逸**：管理员手动追加宿主机目录挂载时，OpenClaw 会做**双重路径校验**——先校验规范化源路径，再沿最深已存在父目录解析真实物理路径；即使目标叶子文件尚未创建、但父目录暗藏指向敏感目录的符号链接，也会直接拒绝挂载。
- **私有托管 Git 工作树（Managed Worktree）**：给沙箱分配项目代码时，创建的是干净的私有检出——不包含宿主机共享 Git 配置、凭据助手和其他分支，且在 Gateway 侧使用受控 Git 配置视图打包，防止恶意仓库里的 `.git` filter 在宿主机上偷偷执行。

## 3. 作用域复用（Scope）与生命周期管理

### 3.1 多会话如何共享或隔离沙箱？
- **三种常规作用域**：`agent`（每个 Agent 独占一个环境）、`session`（每个会话独占一个）、`shared`（全部沙箱会话共享一个）。
- **角色强制沙盒的特殊隔离**：针对带已验证身份的访客（Guest），系统**无视常规 Scope，直接按自然人身份硬隔离**——不同访客绝不共享容器和工作区；一旦某位访客的邀请/访问权限被撤销，Gateway 会自动中止其后台命令并停止对应私有容器。
- **防同键碰撞**：非共享环境的身份标识不仅包含 Agent/Session ID，还绑定了**工作区真实路径**，防止同机多工作区复用同名键时串容器。

### 3.2 空闲休眠与冷热回收
- **15 分钟空闲自动停机**：Gateway 每 5 分钟巡检一次，超过 15 分钟没有新准入（且没有正在运行的回合或持久后台命令）的 Docker/Podman 容器会自动停止——**立即释放内存盘与野进程，但保留工作区文件与容器可写层**，下一轮使用时直接秒启复用，无需重跑初始化脚本。
- **DooD（Gateway 自身跑在容器内）路径自动翻译**：若 OpenClaw Gateway 本身部署在 Docker 里，它通过宿主机 Docker 引擎创建“兄弟沙箱容器”时，会自动校验自身容器身份并将容器内路径翻译成宿主机真实挂载路径；同时严禁把宿主机 Docker Socket 挂载进 Agent 沙箱容器。
