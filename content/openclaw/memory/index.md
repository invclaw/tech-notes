> [!FOCUS] 核心设计思想
> OpenClaw 的记忆系统遵循三条底层原则：**无黑盒隐藏状态**（模型记住的一切都落在本地可见文件与 SQLite 索引里）、**写路径与读路径分离**（日常只做轻量记录，长期沉淀交给后台异步整理）、**写路径即安全边界**（用结构化来源血缘从入口防投毒，而不是事后猜文本安全不安全）。

## 六类记忆速览

OpenClaw 为每个 Agent 分配独立工作区（默认 `~/.openclaw/workspace/`）与独立 SQLite 数据库，按内容性质、权威度与更新节奏将记忆拆分为六个层次：

| 记忆类型 | 物理载体 | 核心存放内容 | 更新节奏 | 是否自动注入上下文 |
|---|---|---|---|---|
| **1. 指令层** | 工作区 `AGENTS.md` / `SOUL.md` 等 | 行为宪法、岗位规程、人格与本地约定 | 仅人类手动修改 | 每次启动**必然注入** |
| **2. 长期事实记忆** | 工作区 `MEMORY.md` | 经验证的稳定事实、架构决策与短摘要 | 显式要求 + 每日后台 Dreaming 提炼 | 启动按预算注入 + 触发词注入 |
| **3. 用户偏好模型** | `USER.md`（多人叠加个人文件） | 稳定偏好、沟通风格（强制祈使句指令） | 原地覆盖更新，不留旧历史 | 启动单独小预算注入 |
| **4. 情景日志层** | `memory/YYYY-MM-DD.md` + SQLite 会话 | 每日工作笔记与完整原始对话 | 每天一份；随时追加 + 压缩前预刷写 | **绝不自动注入** |
| **5. 前瞻意图层** | Cron 定时任务 + SQLite 常驻意图 | 未来某时间或某事件触发时要做的事 | 显式创建；状态机驱动；显式取消 | 仅触发命中时注入 |
| **6. 人工审阅层** | `DREAMS.md` + SQLite 改写前快照 | 后台记忆整理摘要与变更回溯 | 每次 Dreaming 后自动追加 | **永不注入模型** |
