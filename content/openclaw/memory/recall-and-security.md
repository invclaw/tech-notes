> [!NOTE] 本页聚焦
> 回答三个核心问题：**存下来的记忆在对话时怎么被召回？多代码仓库工作时怎么防止经验串台？怎么防止外部网页或群聊把恶意指令投毒进长期记忆？**

## 1. 双车道召回架构（按延迟与成本分流）

OpenClaw 把记忆召回拆成两条成本截然不同的车道，确保普通对话零卡顿、复杂回忆够精准：

### 1.1 车道 1：常驻快车道（零模型调用、零额外延迟）
在每个合格回合自动运行，**完全不调用大模型**：
1. **启动预算注入**：加载通过来源校验的 `MEMORY.md` 与 `USER.md`，长会话每轮自动感知最新整理结果。
2. **多因子加权检索**：混合检索（文本 + 向量）得分乘以**时间衰减（约 30 天半衰期）**与**写入时评定的重要度**，无需在查询阶段再调模型重排，即可兼顾“相关、新鲜、重要”。
3. **触发短语与常驻意图预过滤**：每条入站消息都会用极速规则匹配 `MEMORY.md` / `USER.md` 上的触发短语（专门兼容中文无空格连续分词）以及已武装的常驻意图，高分命中时悄然注入少量隐藏上下文（每轮最多 3 条）。

> [!WARNING] 自动注入的安全红线
> **只有精选核心层（`MEMORY.md` 与 `USER.md`）允许自动注入**。每日笔记与原始会话记录无论匹配分多高，都**绝不**在普通回合自动塞进提示词，只能通过显式检索工具或车道 2 深度召回读取。

### 1.2 车道 2：按需升级（深度召回子 Agent）
仅当同时满足两个固定条件时才启动：
1. 用户消息带有**明确的回忆、跨时间或多跳追问意图**（这恰恰是普通向量检索最薄弱的地方）；
2. **车道 1 没有强命中**。

此时启动独立的深度召回子 Agent 跨历史会话检索阅读，把模型耗时精准花在疑难回忆上。

> [!TIP] 故障降级铁律
> 回复路径上的每一步记忆召回都有超时与兜底机制——记忆子系统哪怕完全宕机，也只会降低召回丰富度，**绝不会阻塞或吃掉一轮正常对话**。

## 2. 项目作用域隔离（多仓库防串台）

当一个 Agent 同时在多个代码仓库间切换工作时，A 项目的构建绕过方案很容易误导 B 项目。OpenClaw 用**基于 Git 仓库的项目作用域**解决这一问题，同时无需把记忆文件拆得支离破碎：

- **统一仓库身份**：以规范化的 `origin` 远程地址作为项目标识，因此同一仓库的普通克隆与多个 Linked Worktree 自动共享同一标识，而 Fork 仓库天然隔离；无 `origin` 时回退到绝对根路径。
- **动态活跃窗口**：每个会话在内存中维护最近活跃的最多 4 个仓库标识（LRU 淘汰）；当前写入的新经验只打上当前仓库标识。
- **差异化检索与注入**：
  - 检索时：**提升**当前活跃仓库的记忆权重，**轻度降权**其他仓库的记忆，未打标签的通用记忆保持中性；
  - 触发词自动注入更严格：带项目标签的条目只有在所属仓库处于当前活跃集时才允许触发；
  - **例外**：`USER.md`（用户偏好）与常驻意图始终属于**用户全局**，不按项目隔离。

## 3. 防投毒安全边界：写路径硬隔离

记忆是提示词注入攻击最垂涎的持久化跳板——一旦恶意指令混进长期记忆，就会在未来每一次对话里反复生效。由于事后靠内容扫描很难可靠识别投毒，OpenClaw 选择在**写入路径做结构化硬隔离**：

### 3.1 不可伪造的来源血缘（Provenance）
每条索引记录都在 SQLite 的独立字段里保存来源等级，**绝不靠解析正文里的自然语言来判断信任度**（正文里自称“主人说的”完全无效）：
- **主人直输（Owner）**：主人在可信渠道亲手输入；
- **可信推导（Agent）**：基于主人输入合理推导的结论；
- **不可信来源（Untrusted）**：来自网页抓取、外部工具返回或群聊非主人成员；
- **系统噪声（System）**：心跳提示、定时任务前导词等运行时指令。
- *保守默认*：无法判定来源时绝不默认标为主人输入。

### 3.2 三条防污染铁律
1. **不可信内容结构性禁入精选层**：在 Dreaming 构建整合提示词**之前**，代码规则就会直接踢掉所有 `untrusted` 和 `system` 候选——这不是扣分惩罚，而是硬前提，**召回再多次也绝不可能晋升进 `MEMORY.md`**。
2. **后台会话禁入长期记忆 + 防回忆闭环**：
   - 定时任务、心跳巡检与子 Agent 会话不产生可晋升长期记忆的候选，彻底杜绝“心跳垃圾占满记忆库”；
   - 凡是从记忆召回后注入上下文的片段都带有结构化标记，**永不被二次提取为新记忆**——同一条事实召回一百次依然只是一条事实。
3. **轮次内污点传播（Turn Tainting）**：
   - 在一轮对话中，只要某个工具返回了声明为网络来源的内容（如抓取网页、浏览器读取、搜索结果），**该轮后续所有模型输出都会自动带上污点**，全部降级按 `untrusted` 分类，直到下一条用户输入才清除污点——从结构上阻断网页隐藏指令洗白混入长期记忆。
